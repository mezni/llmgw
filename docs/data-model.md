# Data model

SQLite schema, migration rules, indexes, and retention for the gateway. The abbreviated schema and its rationale also appear in [architecture §6](architecture.md#6-data-model); this document is the detailed reference. SQL lives only in the `storage` crate (see [ADR 0001](adr/0001-sqlite-first.md) and [conventions.md](conventions.md)).

## 1. Conventions

- IDs are `TEXT` UUIDs generated by the server, except provider IDs, which are human-readable slugs (`anthropic`). Aliases have a UUID `id` plus a unique `name` (`fast`) that clients use.
- Timestamps are `TEXT` in RFC 3339 UTC (`2026-11-20T14:03:11Z`). There are no local-time columns.
- Money is USD `REAL` in V1. Round to cents at the API boundary and compare with a small epsilon; a move to integer minor units is a V3 migration concern.
- Booleans are `INTEGER` 0/1. Encrypted credentials are `BLOB` (AES-256-GCM output, including nonce and tag).
- `NULL` means "unset/unlimited"; do not use sentinel values such as `-1` or `0`.
- `requests` rows are immutable history and deliberately have **no foreign keys** to projects or keys, so cleanup cannot cascade or block retention.
- All writes go through one of two paths: the batched usage writer or an admin mutation. Both run under SQLite WAL mode with `busy_timeout = 5000`.

## 2. Schema

```sql
CREATE TABLE projects (
  id                    TEXT PRIMARY KEY,
  name                  TEXT NOT NULL UNIQUE,
  monthly_budget_usd    REAL,                  -- NULL = unlimited
  monthly_spend_usd     REAL NOT NULL DEFAULT 0,
  spend_period          TEXT NOT NULL,         -- 'YYYY-MM', reset on roll-over
  created_at            TEXT NOT NULL
);

CREATE TABLE api_keys (
  id                    TEXT PRIMARY KEY,
  project_id            TEXT NOT NULL REFERENCES projects(id),
  prefix                TEXT NOT NULL,         -- display only, e.g. 'gw-ab12…'
  key_hash              BLOB NOT NULL UNIQUE,  -- SHA-256 of the secret
  rpm_limit             INTEGER,
  tpm_limit             INTEGER,
  expires_at            TEXT,
  revoked_at            TEXT,
  created_at            TEXT NOT NULL
);

CREATE TABLE key_allowed_aliases (             -- empty = all aliases allowed
  key_id                TEXT NOT NULL REFERENCES api_keys(id),
  alias_id              TEXT NOT NULL REFERENCES aliases(id),
  PRIMARY KEY (key_id, alias_id)
);

CREATE TABLE providers (
  id                    TEXT PRIMARY KEY,       -- 'anthropic', 'openai'
  kind                  TEXT NOT NULL,          -- adapter type
  base_url              TEXT NOT NULL,
  credentials_enc       BLOB NOT NULL,          -- encrypted at rest
  timeout_ms            INTEGER NOT NULL,
  enabled               INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE models (
  id                    TEXT PRIMARY KEY,
  provider_id           TEXT NOT NULL REFERENCES providers(id),
  upstream_name         TEXT NOT NULL,          -- real upstream model name
  input_price_per_mtok  REAL NOT NULL,
  output_price_per_mtok REAL NOT NULL,
  cached_input_price_per_mtok REAL
);

CREATE TABLE aliases (
  id                    TEXT PRIMARY KEY,
  name                  TEXT NOT NULL UNIQUE,   -- 'fast', 'smart'
  max_attempts          INTEGER NOT NULL DEFAULT 2,
  timeout_ms            INTEGER
);

CREATE TABLE alias_targets (
  alias_id              TEXT NOT NULL REFERENCES aliases(id),
  position              INTEGER NOT NULL,       -- 0 = primary, 1+ = fallbacks
  model_id              TEXT NOT NULL REFERENCES models(id),
  PRIMARY KEY (alias_id, position)
);

CREATE TABLE requests (
  id                    TEXT PRIMARY KEY,       -- X-Request-Id or generated UUID
  ts                    TEXT NOT NULL,
  project_id            TEXT NOT NULL,          -- no FK, intentionally
  key_id                TEXT NOT NULL,          -- no FK, intentionally
  alias                 TEXT NOT NULL,
  tag                   TEXT,                   -- X-Gateway-Tag
  provider_id           TEXT,                   -- final provider used
  model                 TEXT,                   -- final upstream model
  stream                INTEGER NOT NULL,
  input_tokens          INTEGER,
  output_tokens         INTEGER,
  cached_tokens         INTEGER,
  cost_usd              REAL,
  latency_ms            INTEGER,
  ttft_ms               INTEGER,
  status                TEXT NOT NULL,          -- ok | error | client_cancelled | ...
  http_status           INTEGER,
  error_kind            TEXT,
  attempts_json         TEXT,                   -- per-attempt outcomes
  request_body          TEXT,                   -- only with full logging
  response_body         TEXT                    -- only with full logging
);

CREATE TABLE admin_users (
  id            TEXT PRIMARY KEY,
  email         TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,                  -- Argon2
  role          TEXT NOT NULL,
  created_at    TEXT NOT NULL
);

CREATE TABLE audit_log (
  id          TEXT PRIMARY KEY,
  ts          TEXT NOT NULL,
  admin_id    TEXT REFERENCES admin_users(id),
  action      TEXT NOT NULL,
  target      TEXT,
  detail_json TEXT
);
```

`monthly_spend_usd` is updated on the request path through a bounded writer, separately from the droppable `requests` log channel. A dropped log event therefore cannot bypass a budget (see [security.md §7](security.md#7-abuse-and-reliability-controls)).

There is no `config_versions` table in V1: routing config is derived from the normalized tables, rebuilt into an immutable snapshot after each admin mutation, and swapped atomically. Audit rows record who changed what.

## 3. Indexes

| Index | Purpose |
|-------|---------|
| `UNIQUE(api_keys.key_hash)` | Constant-time key lookup; uniqueness prevents duplicate secrets |
| `UNIQUE(projects.name)`, `UNIQUE(aliases.name)`, `UNIQUE(admin_users.email)` | Natural-key integrity |
| `idx_requests_project_ts (project_id, ts)` | Dashboard and usage queries filtered by project and time range |
| `idx_requests_alias_ts (alias, ts)` | Usage grouped by alias |
| `idx_requests_ts (ts)` | Retention sweep and global time buckets |
| `idx_requests_status_ts (status, ts)` | Error-rate charts and incident queries |
| `idx_api_keys_project (project_id)` | Admin list of a project's keys |
| `idx_models_provider (provider_id)` | Provider/model pages and snapshot rebuilds |
| `PRIMARY KEY (alias_id, position)` on `alias_targets` | Ordered fallback chain, no separate index |
| `PRIMARY KEY (key_id, alias_id)` on `key_allowed_aliases` | Allowlist check, no separate index |
| `idx_audit_log_ts (ts)` | Audit page time filtering and retention |

All indexes are defined in the migration that creates their table. Dashboard time series use `GROUP BY` over `requests`; add rollup tables only when measured query time justifies it.

## 4. Migrations

- Location: `crates/storage/migrations/` with `sqlx migrate`. Names are monotonic: `V0001__init.sql`, `V0002__add_spend_period.sql`, and so on. Never edit an applied file.
- Migrations are forward-only. To correct a mistake, add a new migration. No `down` scripts in production.
- Each migration runs in a single transaction and must leave the schema usable by the previous binary (expand → backfill → contract across releases).
- Additive first: add a nullable column, backfill in a second migration, then add `NOT NULL` in a third. Avoid rewriting large tables in one step.
- New tables that grow without bound need an index on `ts` and a retention rule in §5 before the migration is merged.
- Set `PRAGMA journal_mode = WAL`, `PRAGMA busy_timeout = 5000`, and `PRAGMA foreign_keys = ON` on every connection, not just at startup.
- Seeds (bootstrap admin, default aliases) come from a dedicated migration or from env vars on first start, never from application code on every boot.
- CI runs `sqlx migrate run` against a fresh database and verifies the resulting schema before tests.
- V3 Postgres parity is a separate migration set behind repository traits; schema differences must be documented in that sprint, not hidden in handlers.

## 5. Retention

| Data | Retention | Action |
|------|-----------|--------|
| `requests` metadata rows | 90 days | Delete in batches of at most 10,000 rows, ordered by `ts` |
| `requests.request_body` / `response_body` | 7 days | Null the two columns in batches; metadata row stays until its 90-day expiry |
| `audit_log` | 365 days | Delete in batches; export first if the operator needs longer history |
| Revoked/expired `api_keys` | 30 days after `revoked_at` or `expires_at` | Hard-delete the row and its allowlist entries; the hash is never reused |
| Projects, providers, models, aliases | Until explicitly deleted | Delete via the admin API, which writes an audit row and reloads the snapshot |
| Admin sessions | Browser cookie lifetime | No session rows in V1; logout clears the cookie |
| Config snapshot | In-memory only | Rebuilt from normalized tables after each mutation |

Rules for the cleanup job (S7 task 7.6):

- Runs once per day outside peak hours; one iteration is bounded by row count and duration so WAL growth stays predictable.
- Logs only counts and duration. It never logs request bodies, keys, or agent emails.
- Uses the `ts` index; it never deletes `audit_log` with a cascade from another table.
- The 7-day body purge is independent of the 90-day row purge: metadata remains available for usage and cost reporting after content is gone.
- Operators can shorten retention through configuration but cannot extend it beyond the documented defaults without accepting larger backups.
